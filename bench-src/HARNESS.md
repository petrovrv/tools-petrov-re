# Benchmark harness — tools.petrov.re

## Layout
- Site (live copy, editable): `/root/site/*.html`
- Benchmarks: `/root/bench/`
  - `ref/<tool>_ref.json`  — reference cases generated by an INDEPENDENT implementation (python) or closed-form analytics
  - `run_<tool>.mjs`       — Playwright driver: sets DOM inputs, reads DOM outputs, compares
  - `results/<tool>.json`  — machine-readable result (schema below)

## Hard facts about the tools
- Every tool is a single self-contained HTML file. **All JS is inside an IIFE — there are NO globals.**
  You MUST drive the tool through the DOM: set `<input>`/`<select>` values, dispatch
  `new Event('input',{bubbles:true})` AND `new Event('change',{bubbles:true})`, click the compute
  button if there is one, then read result nodes' `innerText`.
- Unit `<select>` options are often repopulated when the quantity `<select>` changes — always set the
  quantity first, wait ~30 ms, then pick the unit by matching `option.value` OR `option.text`.
- Open pages as `file:///root/site/<file>.html?lang=en` so labels are English and stable.
- Capture `page.on('pageerror')` — silent JS exceptions are themselves findings.

## Playwright
```js
import { chromium } from '/home/claude/.npm-global/lib/node_modules/playwright/index.mjs';
```
Do NOT run `playwright install`. Chromium is preinstalled.

## Reference sources — rules
- The reference MUST be independent of the tool. Acceptable: `iapws`, `CoolProp` (installed),
  closed-form analytic solutions you derive and implement in python, or published standard
  verification tables that you quote with a citation.
- If you use a published table, cite it precisely (standard number, table number) in the result JSON.
- Where two independent references exist, compute both and record their mutual deviation as
  `crosscheck`. Never claim a tool is wrong when the two references disagree by more than the
  tolerance — flag it instead.
- WebSearch is available. Use it to find authoritative verification cases. Prefer primary sources
  (standards bodies, NASA/NACA reports, textbook worked examples with full data).

## Result JSON schema (write exactly this)
```json
{
  "tool": "<manifest id>",
  "file": "<file>.html",
  "reference": "one-line description of the reference and its provenance",
  "reference_citations": ["..."],
  "tolerance": "human-readable statement of the pass criterion",
  "total": 0, "passed": 0, "failed": 0,
  "page_errors": [],
  "cases": [
    {"id":"", "note":"", "inputs":{}, "cmp":{"<qty>":{"got":0,"ref":0,"rel":0,"ok":true}},
     "worst_rel":0, "pass":true}
  ]
}
```

## Tolerances — be honest
Pick the tolerance from the physics, not from what makes the tool pass:
- Closed-form / standard formulation the tool claims to implement → tight (1e-3 relative or better).
- Empirical correlation with published scatter → state the scatter and test the correlation itself,
  not the underlying physics.
- Display rounding: read how many digits the tool prints and never demand more precision than that.
  If the tool prints 5 significant digits, a tolerance below ~1e-5 is meaningless.

## What counts as a finding
1. Numerical disagreement beyond tolerance.
2. Blow-ups / NaN / negative physical quantities.
3. A region/validity range silently extrapolated instead of refused.
4. A JS exception in the console.
5. A label or unit that contradicts the number shown.

Report findings even if you cannot fix them.
